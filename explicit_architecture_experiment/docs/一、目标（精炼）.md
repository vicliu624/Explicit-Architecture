

# **语义耦合度（Semantic Coupling）指标定义**

在本研究中，我们提出用于度量软件模块之间语义关联强度的**语义耦合度（Semantic Coupling, SC）**指标。该指标旨在在结构依赖、表层词汇特征以及深层语义表示三个层面上综合反映模块间的语义相关性，从而为分析架构形式对生成式模型行为的影响提供可量化基础。

给定两个软件模块 $M_i$ 与 $M_j$，定义其语义耦合度 $SC(i,j)$ 为以下三部分的加权组合：
$$
SC(i,j)=\alpha\, S_{\text{struct}}(i,j)+\beta\, S_{\text{lex}}(i,j)+\gamma\, S_{\text{sem}}(i,j),
$$
其中 $$\alpha\+\beta\+\gamma\=1$$，分别对应结构耦合、词汇耦合与语义嵌入相似度的重要性权重。

------

## **1. 结构耦合度 $S_{\text{struct}}(i,j)$**

结构耦合度用于表征模块之间基于静态分析得到的显式依赖关系。
 我们将模块间的多类型依赖统一建模为加权图，并令：
$$
S_{\text{struct}}(i,j)=\frac{\sum\limits_{t\in T} w_t\, d_t(i,j)}{\sum\limits_{t\in T} w_t},
$$
其中：

- $T$ 为依赖类型集合（如调用、字段访问、继承、实现等），
- $d_t(i,j)\in[0,1]$ 为依赖类型 $t$ 下的归一化依赖强度，
- $w_t$ 为依赖类型权重，用于反映不同依赖的语义重要性。

该定义使结构耦合度成为对多类静态依赖的统一度量。

------

## **2. 词汇耦合度 $S_{\text{lex}}(i,j)$**

词汇耦合度用于刻画模块源代码在表层词汇层面的相似性。
 对模块源代码进行分词与 TF–IDF 表示后，定义：
$$
S_{\text{lex}}(i,j)=\cos \bigl(\text{TFIDF}(M_i), \text{TFIDF}(M_j)\bigr),
$$
其中余弦相似度范围为 $[0,1]$。
 该指标反映了模块间命名、标识符与文本模式的一致性。

------

## **3. 深层语义相似度 $S_{\text{sem}}(i,j)$**

深层语义相似度基于预训练代码模型对模块的语义表征。
 令 $\mathbf{e}_i$ 与 $\mathbf{e}_j$ 分别为模块 $M_i$、$M_j$ 由代码表示模型（如 CodeBERT、GraphCodeBERT、StarCoder embedding）生成的向量表示，则定义：
$$
S_{\text{sem}}(i,j)=\cos(\mathbf{e}_i, \mathbf{e}_j).
$$
该部分用于捕捉 API 交互语义、方法职责、行为概念等深层语义关联。

------

## **4. 综合语义耦合度**

最终指标 $SC(i,j)\in[0,1]$ 为上述三项的加权合成，形成跨层级、可解释、可量化的模块语义相关性度量。
 该定义允许在后续实验中分别分析不同语义来源对生成模型性能的影响，并支持消融实验、对比实验及跨项目可比性。

# 一、目标（精炼）

量化每对模块/类之间的“语义耦合度”为一个实数 (SC(i,j)\in[0,1])，同时提供模块总体耦合度分布、耦合网络（加权图），并能用历史变更/运行时数据进行验证与校准。

------

# 二、核心思想（三维合成）

语义耦合不是单一维度可度量，建议用**结构耦合（Structural） + 词汇/符号耦合（Lexical） + 语义相似度（Semantic）**三部分加权合成：
$$
 SC(i,j) = \alpha \cdot S_{struct}(i,j) + \beta \cdot S_{lex}(i,j) + \gamma \cdot S_{sem}(i,j)
$$
其中 (\alpha+\beta+\gamma=1, \alpha,\beta,\gamma\ge0)。默认初始权重可设为 (\alpha=0.4,\beta=0.2,\gamma=0.4)（可后续用回归基于 co-change 校准）。

下面逐项给出可计算定义与实现方法。

# 三、子指标定义与计算方法

## 1) 结构耦合 (S_{struct}(i,j))（静态依赖强度）

**含义**：模块间的静态依赖（调用、继承、字段/类型引用、包导入等）的强弱。

**计算步骤**：

1. 对工程做静态分析，得到模块级依赖边（建议以 class 或 package 为节点，取决于粒度）。
   - 工具：`jdeps`（JDK自带）、JavaParser、Spoon、antlr 或 tree-sitter + 自写解析脚本。
   - 提取边类型与权重：方法调用、字段访问、继承/实现、静态引用、异常引用等。
2. 对每种边定义基本权重 (w_{edgeType})。例如：
   - method call = 1.0
   - field access = 0.8
   - inheritance/implements = 0.9
   - static import = 0.6
3. 对模块对 (i,j) 计数所有边并归一化：
    $$
    S_{struct}(i,j) = \frac{\sum_{e\in E_{i\to j}} w_{type(e)}}{\max_{p,q}\sum_{e\in E_{p\to q}}w_{type(e)}}
    $$
    （结果归一化到 [0,1]）

**实现提示**：

- 输出：加权有向邻接矩阵 (A_{struct})。
- 若用 class 级别再聚合到 package：对 package 求 sum 或平均（按类数加权）。

------

## 2) 词汇耦合 (S_{lex}(i,j))（名字与注释共现相似度）

**含义**：模块之间在标识符/注释/文档层面的词汇相似性（表面语义）。

**计算步骤**：

1. 为每个模块提取文本语料：
   - 类名、方法名、参数名、常量名、Javadoc、注释、日志字符串。
   - 可以选择保留驼峰拆分与下划线拆分后的小词（tokenize）。
2. 构建模块级 TF-IDF 向量或使用 HashingTF：
   - 工具：scikit-learn 的 `TfidfVectorizer`（如果离线）；也可用 Lucene/Elasticsearch。
3. 计算模块对之间的余弦相似度：
    $$
    S_{lex}(i,j)=\cos(\mathrm{TFIDF}_i,\mathrm{TFIDF}_j)
    $$
    归一化到 [0,1]（余弦自然在[-1,1]，但词频向量一般非负，范围 [0,1]）。

**实现提示**：

- 先做词形还原（stemming）或保留原形。移除常见 stopwords（如 get,set,impl）。
- 输出：词汇相似度矩阵 (A_{lex})。

------

## 3) 语义耦合 (S_{sem}(i,j))（基于代码/注释的语义向量相似度）

**含义**：利用代码/注释的语义嵌入（code embeddings / code+doc embeddings）计算更深层的语义相关度，能捕捉功能/意图相近但表面不同的模块。

**计算步骤**：

1. 选择 embedding 模型（离线/本地或 API）：
   - 可选开源模型：CodeBERT、GraphCodeBERT、bge-small（若你本地有），或 sentence-transformers 风格的 code 模型。
   - 如果你后续要把结果与 Transformer 生成能力对应，优先用与实验模型同类型或任务相关的 embedding 模型（可校准）。
2. 对模块做分段嵌入：
   - 最可靠：对每个函数/方法生成 embedding，再对模块内方法 embedding 做加权平均（长度或调用频次权重）。
   - 也可以把类级源码片段（包括注释）拼成一个文本块直接 embed（要注意长度截断）。
3. 计算模块对余弦相似度：
    $$
    S_{sem}(i,j)=\cos(\mathrm{embed}_i,\mathrm{embed}_j)
    $$
    结果自然落在 ([-1,1])，映射到 [0,1]： ((x+1)/2) 或如无负值直接归一化。

**实现提示**：

- 若使用 sentence-transformers，示例（伪代码）：
  - `emb = model.encode(list_of_code_snippets, batch_size=32)`
  - `module_emb = np.mean(emb_for_methods_in_module, axis=0)`
- 输出：语义相似度矩阵 (A_{sem})。

------

# 四、合成与归一化

对三个矩阵按权重合成：

1. 先确保每个矩阵都归一化到 [0,1]（例如除以各自最大值或使用 min-max）。
2. 合并：
    $$
    SC(i,j) = \alpha A_{struct}(i,j) + \beta A_{lex}(i,j) + \gamma A_{sem}(i,j)
    $$
3. 如果要一个模块总体耦合度（到其他所有模块的“耦合中心性”）：
    $$
    SC_{out}(i)=\sum_j SC(i,j),\quad SC_{in}(j)=\sum_i SC(i,j)
    $$
    或标准化为平均值。

# 六、验证与校准（非常关键）

要让这个数字有意义，必须**用工程信号验证并校准权重**：

## 验证信号 A：历史共变（Co-change）

- 从 Git 提取文件/类的 co-change 频率（同一次 commit 中同时被修改的文件对数）。
- 计算 co-change 矩阵 (C(i,j))：共现次数或归一化后的概率。
- 期望：(SC(i,j)) 与 (C(i,j)) 有正相关。用 Spearman/Pearson 计算相关系数并报告 p-value。

## 验证信号 B：运行时耦合（如果可用）

- 通过调用跟踪/覆盖率（JaCoCo/tracing）提取实际运行时跨模块调用权重，形成矩阵 (R(i,j))；比较与 (SC) 的相关性。

## 校准权重

- 用线性回归或正则化回归（ridge）以 (C(i,j)) 或 (R(i,j)) 为目标，拟合权重 (\alpha,\beta,\gamma)：
   $$
   \min_{\alpha,\beta,\gamma}\sum_{i,j} \left(C(i,j) - (\alpha S_{struct}+\beta S_{lex}+\gamma S_{sem})_{i,j}\right)^2
   $$
   并加上约束（和为1、非负）。这样得到的权重就是数据驱动的最优组合。

# 七、统计检验与显著性

- 相关性检验：Spearman ρ 与 p-value（更稳健于非线性关系）。
- 回归解释度：R², adjusted R²。
- 对比不同指标的单独解释力（单变量回归）以检验哪部分贡献最大。

# 十、快速示例（伪代码片段，直接可用做实现参考）

### 抽取方法文本并计算 module-level embedding（Python 伪码）

```python
# 假设 methods_by_module: dict[module] -> list[str] (method source + javadoc)
from sentence_transformers import SentenceTransformer
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity

model = SentenceTransformer('microsoft/codebert-base')  # 可换
module_embs = {}
for mod, methods in methods_by_module.items():
    embs = model.encode(methods, show_progress_bar=False)
    module_embs[mod] = np.mean(embs, axis=0)

mods = list(module_embs.keys())
M = len(mods)
A_sem = np.zeros((M,M))
for i in range(M):
    for j in range(M):
        A_sem[i,j] = cosine_similarity(module_embs[mods[i]].reshape(1,-1),
                                       module_embs[mods[j]].reshape(1,-1))[0,0]
# map from [-1,1] to [0,1]
A_sem = (A_sem + 1.0) / 2.0
```

### 构造结构耦合（示意）

- 用 jdeps 或 AST visitor 输出三元组 `(from_module, to_module, edge_type)`，再用 pandas 汇总并归一化。

# 十一、常见问题与应对

- **如果测试覆盖率低，co-change 校验不可靠**：优先用运行时 traces 或人工标注小样本做验证；或补充最小行为测试集。
- **embedding 长度截断问题**：用函数级分片嵌入再聚合，避免跨越模型上下文长度上限。
- **方法/类数量级相差大导致偏差**：在聚合时对模块内方法 embedding 做加权或使用 median 而不是 mean。
- **闭源模型获取 attention 不可行**：可用替代代理信号（embedding 聚类、一致性）或改用开源模型来获取内部矩阵。
